The three configurations

A real channel takes a real constellation, a complex channel a complex one. Every table below sits in exactly one of these; nothing is measured outside them.

BPSK · AWGN

Calibration. The only channel with exact closed forms, so it is where the simulator is proved correct. No relay is ranked on it.

QPSK · Rayleigh

Canonical. The operating point every conclusion rests on. One bit per axis of the plane the channel acts in.

16-QAM · Rayleigh

Extension. Four levels per axis, which breaks the per-axis relay formulation. Same channel as canonical.

Reading BER across configurations

The SNR argument sets noise from average symbol energy, so it is Es/N0 everywhere. Eb/N0 is the same number for BPSK, 3.01 dB lower for QPSK and 6.02 dB lower for 16-QAM. The three are not on a common abscissa.

VAE convention A/B — a hypothesis refuted

The thesis reports the VAE relay “pinned at 0.25–0.40 at every SNR, meaning it never learns the task”. That failure no longer reproduces anywhere. The working explanation was the 3 dB SNR-convention bug, since learned relays draw their training data through the corrected channel. This test isolates it: evaluation is on Rayleigh, untouched by the fix, so the only difference between arms is the convention used to synthesise training data.

Both arms behave identically. Training on 3 dB-hot data does not break the VAE, so the convention bug is not the cause.

What actually changed

The published VAE numbers date from 23 March. relaynet/relays/vae.py — the implementation used today — was first committed on 1 April. The failing result therefore came from a different VAE implementation entirely, one that predates the ported relay. The convention bug is exonerated; the reimplementation is the explanation.

This matters for the write-up: five passages in Chapters 2, 5 and 8 still argue from the VAE failure, including a paradigm-level caveat about generative relaying. They cannot be repaired by blaming the SNR bug.

Not covered here: tbl:table13 and tbl:table25 report wall-clock timing, which is machine-dependent and measured on different hardware. The verifier checks their parameter counts but reports timings as informational rather than pass/fail.
